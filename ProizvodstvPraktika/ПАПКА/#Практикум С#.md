## 2. Единая точка входа (консольное меню)

### 2.1. Формат приложения

- Консольное приложение .NET.
- **Единая точка входа** — программа запускается и показывает меню выбора задания.
- Пользователь вводит **номер задания** и запускается именно это задание.
- Есть команда выхода (`0` или `q`).
### 2.2. Поведение меню

**Главное меню:**

``` text
=== Практикум по C# ===
1. Уровень 1 — Базовый (задания 1–15)
2. Уровень 2 — Средний (задания 16–35)
3. Уровень 3 — Продвинутый (задания 36–50)
4. Выход
   
Выберите уровень:
```

**Меню уровня** (пример для уровня 1):

```text 
--- Уровень 1: Базовый ---
1. Hello, World + текущая дата
2. Переменные примитивных типов
3. Калькулятор с делением на ноль
...
4. Git: локальный репозиторий
5. Назад
   
Выберите задание:
```

---

### 2.3. Запуск задания

При выборе задания:
1. Выводится **описание задания** (что нужно было сделать, требования, ожидаемый результат).
2. Выводится подсказка — какие классы/методы/пространства имён можно использовать.
3. Запускается решение.
4. После завершения — пауза «Нажмите Enter для возврата в меню».

**Пример вывода:**

``` text
==================================================
Задание 3. Калькулятор
--------------------------------------------------
Описание:
  Принимает два числа и оператор (+, -, *, /),
  выводит результат. Обработать деление на ноль.
  
Требования:
  - Использовать switch для оператора
  - Не допускать падения при делении на ноль
--------------------------------------------------
[запуск решения...]

Нажмите Enter для возврата в меню...
```

## 3. Требования к коду

### 3.1. Структура проекта

```text
CSharpPracticum/
├─ Program.cs              // точка входа, главное меню
├─ Menu/
│  ├─ MenuRunner.cs        // логика меню
│  └─ LevelMenu.cs
├─ Tasks/
│  ├─ Level1/
│  │  ├─ Task01_HelloWorld.cs
│  │  ├─ Task02_Primitives.cs
│  │  └─ ...
│  ├─ Level2/
│  └─ Level3/
├─ Common/
│  ├─ ITask.cs             // интерфейс задания
│  ├─ TaskInfoAttribute.cs // атрибут с описанием
│  └─ ConsoleHelper.cs
└─ README.md
```

### 3.2. Обязательный контракт задания

Каждое задание реализует единый интерфейс (или использует атрибут с метаданными):

```csharp
public interface ITask
{
    string Title { get; }
    string Description { get; }
    string[] Requirements { get; }
    void Run();
}
```

**Требования:**
- Каждое задание — **отдельный класс**.
- Класс хранит: `Title`, `Description`, `Requirements`, метод `Run()`.
- Меню **не должно** содержать логику заданий — только регистрацию и вызов.
### 3.3. Правила оформления

- Один файл — один класс задания.
- Имя файла: `TaskNN_КраткоеИмя.cs` (NN — номер задания).
- Все публичные члены — с XML-комментариями (`///`).
- Никакой логики в `Program.cs`, кроме запуска меню.
- Форматирование — по умолчанию `dotnet format` / `.editorconfig`.

## 4. Требования к работе с Git

Все задания сдаются через Git-репозиторий. Ниже — что именно требуется и как это проверяется.
### 4.1. Общие правила

1. **Репозиторий** — на GitHub или GitLab. Ссылку интерн присылает ментору.
2. **Главная ветка** называется `main`. Она всегда должна собираться (`dotnet build` без ошибок).
3. **Один коммит = одно задание** (минимум). В сообщении коммита обязательно указывается номер задания.
4. **Сообщения коммитов** — по шаблону Conventional Commits:

- `feat: task 05 - multiplication table`
- `fix: task 03 - handle division by zero`
- `docs: task 15 - add git notes`
- `refactor: task 09 - extract array helpers`

5. **`.gitignore`** обязателен в корне репозитория. В него обязательно входят:

- bin/
- obj/
- .vs/
- .idea/
- *.user
- *.suo

Проверка: `git status` не должен показывать файлы из этих папок.
### 4.2. Ветки

- `main` — стабильная ветка. Сюда попадает только рабочий код.
- Для каждого уровня создаётся отдельная ветка: `level-1`, `level-2`, `level-3`.
- После завершения уровня ветка вливается в `main` через merge (или PR).

**Как проверяется:** в репозитории видны все ветки, история merge-коммитов присутствует.
### 4.3. Файл `git-notes.md`

- Файл `git-notes.md` лежит в корне репозитория.
- Заполнен по шаблону (по каждому git-заданию — команды, вывод, выводы):

## 5. Требования к сдаче

### 5.1. Что сдаем

1. Ссылка на репозиторий (с полной историей, все ветки).
2. `README.md` в корне с:
    - инструкцией по запуску;
    - таблицей заданий и статусом («выполнено / в работе»);
    - краткими заметками по каждому уровню (что было сложно, что узнал).
3. Заполненный файл `git-notes.md` — вывод ключевых команд, использованных в git-заданиях (для проверки).
### 5.2. Критерии оценки задания (каждое)

- Код собирается без ошибок и предупреждений.
- Задание встроено в меню и запускается по номеру.
- Выводится описание и требования перед запуском.
- Решение соответствует требованиям задания.
- Обработка крайних случаев (некорректный ввод, пустые значения).
- Код читаемый: осмысленные имена, разбиение на методы, без дублирования.
- Для git-заданий — команды выполнены, история корректна.

- Проверка: ревью репозитория + демо запуска меню + защита 2–3 случайных заданий.
